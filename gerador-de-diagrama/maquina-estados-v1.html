🤖 Prompt para IA — Gerar Máquina de Estados Mermaid
Cole este prompt em qualquer IA (ChatGPT, Claude, Gemini…) junto com a descrição do seu sistema. Ele garante que o diagrama gerado siga a sintaxe stateDiagram-v2 do Mermaid e que os estados sigam boas práticas de nomenclatura e transições.
Gere um diagrama de máquina de estados em Mermaid (stateDiagram-v2) para o sistema descrito abaixo. ## Regras obrigatórias de sintaxe 1. Use stateDiagram-v2 (versão 2 — suporta setas bidirecionais e anotações modernas). NÃO use stateDiagram (legado). 2. Cada estado é declarado em sua própria linha com a sintaxe NOME: Rótulo legível. Use nomes curtos em PascalCase no identificador e um rótulo descritivo entre dois pontos. 3. Os estados inicial e final usam o marcador [*]: • [*] --> Inativo (estado inicial) • Ativo --> [*] (estado final — máquina pode ter vários finais) 4. Transições usam ESTADO1 --> ESTADO2: evento(). O texto após os dois pontos é o evento/gatilho, preferencialmente com verbo no infinitivo e parênteses indicando ação. 5. Cada estado deve ter pelo menos uma transição de entrada e, exceto estados finais, pelo menos uma transição de saída. 6. NÃO use palavras reservadas como identificadores de estado (state, direction, classDef, note, transition etc.). Se precisar, use um nome alternativo como State_ ou St_. 7. NÃO repita declarações de estado. Se um estado aparece em uma transição, ele é automaticamente conhecido — não é necessário redeclará-lo. A declaração com rótulo é necessária somente se você quer um rótulo legível diferente do identificador. 8. Para notas explicativas use note right of ESTADO: ou note left of ESTADO: seguido do texto. Use \n para quebrar linhas dentro da nota. 9. Use direction LR (esquerda para direita) ou direction TB (cima para baixo) no início do diagrama se quiser forçar a direção. 10. Não inclua blocos de configuração Mermaid (%%{init}%%) — o tema já está configurado externamente. ## Regra geral (decorar!) Sempre use stateDiagram-v2, declare os estados com rótulo legível uma única vez e mantenha as transições no formato DE --> PARA: evento(). ## Estrutura esperada stateDiagram-v2 direction LR [*] --> EstadoInicial EstadoInicial: Estado Inicial Ativo: Ativo EmProcesso: Em Processo Concluido: Concluído Erro: Erro Cancelado: Cancelado EstadoInicial --> Ativo: iniciar() Ativo --> EmProcesso: executar() EmProcesso --> Concluido: finalizar() EmProcesso --> Erro: falhar() Erro --> EstadoInicial: reiniciar() Concluido --> [*] Cancelado --> [*] note right of EmProcesso : Lógica de negócio\nem execução note left of Erro : Estado de falha\nrecuperável ## Sistema a documentar [DESCREVA AQUI: entidade ou sistema, seus estados possíveis, eventos que disparam transições, condições de guarda, estados finais aceitáveis]
