🤖 Prompt para IA — Gerar Diagrama de Sequência Mermaid
Cole este prompt em qualquer IA (ChatGPT, Claude, Gemini…) junto com a descrição do seu caso de uso. Ele garante que o diagrama gerado siga as boas práticas de ativação de lifelines e não cause erros no Mermaid.
Gere um diagrama de sequência em Mermaid (sequenceDiagram) para o caso de uso descrito abaixo. ## Regras obrigatórias de sintaxe 1. Declare os participantes no topo usando actor para humanos e participant para sistemas. 2. Use ->>+ para ativar e -->>- para desativar lifelines. 3. NUNCA use -->>- nem deactivate dentro de ramos alt/else/opt para participantes cuja lifeline foi ativada antes do bloco. O Mermaid processa os ramos do alt/else em sequência linear — não de forma bifurcada — então o deactivate do ramo de erro "consome" a ativação, e quando o ramo else chega, o participante já está em 0, causando erro "inactivate inactive participant". Resolva assim: • Mova a resposta desativadora (-->>-) para antes do bloco alt, ou • Use deactivate PARTICIPANTE depois do end. • Dentro dos ramos, use setas simples (-->>) sem o - de desativação. 4. Use deactivate PARTICIPANTE explícito após o end do bloco alt/opt quando a lifeline foi aberta antes do bloco — isso garante que o fechamento cubra todos os ramos de forma simétrica. 5. Coloque a condição de cada ramo entre colchetes no título do alt / else / opt. Exemplo: alt [sem dados registrados] 6. Use Note over PARTICIPANTE: apenas para informações técnicas relevantes de um único componente (ex: lista de campos calculados). Não use para descrever processo — isso vai para o texto da seta. 7. O texto das setas deve ser descritivo: prefira consultarVendas(periodo) + consultarEstoque() a apenas query. 8. Respostas de retorno usam -->> (tracejado). Chamadas usam ->> (sólido). 9. Não inclua blocos de configuração Mermaid (%%{init}%%) — o tema já está configurado externamente. ## Regra geral (decorar!) Nunca use -->>- ou deactivate dentro de ramos alt/else para participantes ativados antes do bloco — deixe o fechamento para depois do end. ## Estrutura esperada sequenceDiagram actor ATOR as Nome do Ator participant SIS1 as Nome Sistema 1 participant SIS2 as Nome Sistema 2 participant SIS3 as Nome Sistema 3 ATOR->>+SIS1: ação do ator SIS1-->>ATOR: feedback imediato SIS1->>+SIS3: consulta de dados SIS3-->>-SIS1: dados / erro ← desativa SIS3 ANTES do alt alt [condição de erro] SIS1-->>ATOR: mensagem de erro ← seta simples, sem desativar SIS1 else [condição de sucesso] SIS1->>+SIS2: chamada ao sistema 2 SIS2-->>-SIS1: retorna dados ← SIS2 ativado e desativado DENTRO do ramo, OK SIS1-->>ATOR: resultado com sucesso ← seta simples end deactivate SIS1 ← fecha SIS1 DEPOIS do end, cobre os dois ramos opt [fluxo opcional — descreva a condição] ATOR->>+SIS1: ação opcional SIS1-->>-ATOR: resposta ← OK: ativou e desativou dentro do mesmo bloco end ## Caso de uso a documentar [DESCREVA AQUI: atores, sistemas envolvidos, fluxo principal, fluxos alternativos e regras de negócio]
